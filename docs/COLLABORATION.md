# Как работать над сайтом Таубер вдвоём

Проект — сайт компании Таубер. Дизайн перенесён из Claude Design, дальше наполняем его содержанием: характеристиками продукции, текстами, фотографиями.

Работают двое. Правки каждого попадают к другому через GitHub.

## Один раз: забрать проект себе

```
git clone https://github.com/dgorshenin555-commits/tauber-web.git
cd tauber-web
```

Дальше три настройки, тоже один раз:

```
git config user.name "Имя Фамилия"
git config user.email "ваш-логин@users.noreply.github.com"
git config core.hooksPath .githooks
```

Про почту: служебный адрес `@users.noreply.github.com` привязывает коммиты к вашему аккаунту GitHub, но не показывает личную почту в истории проекта. Подставьте свой логин на GitHub.

Последняя строка включает защиту от случайной ошибки — см. ниже.

## Главное правило: в main напрямую не пишем

`main` — это то, что опубликовано на сайте. Она обновляется только через pull request, то есть через предложенную правку, которую видит второй участник.

Если попробовать отправить изменение прямо в `main`, git откажется и подскажет, что делать. Именно для этого нужна настройка `core.hooksPath` — без неё защиты не будет.

## Как внести правку

Сначала забрать свежее:

```
git switch main
git pull
```

Создать ветку под свою правку — имя любое, лишь бы понятное:

```
git switch -c pravki-harakteristik-s1201
```

Поправить что нужно, затем:

```
git add -A
git commit -m "Характеристики S1201: добавлены габариты и вес"
git push -u origin pravki-harakteristik-s1201
```

Предложить правку к слиянию:

```
gh pr create --fill
```

После этого второй участник смотрит правку и сливает её. Сайт пересоберётся сам.

Если `gh` не установлен — ссылку на создание pull request git выведет прямо в терминале после `push`, можно открыть её в браузере.

## Как забрать правки второго участника

```
git switch main
git pull
```

Делайте это перед началом любой работы. Тогда вы всегда правите свежую версию, и конфликтов не будет.

## Где что лежит

`content/` — **содержание сайта**. Тексты, характеристики, описания товаров. Здесь и идёт основная работа по наполнению. Правки тут не могут сломать вёрстку.

`src/` — вёрстка и оформление: шаблоны страниц, блоки, цвета, шрифты. Меняется, когда нужно поменять внешний вид.

`public/` — изображения и шрифты, которые отдаются посетителю.

`design/` — эталон: исходный прототип из Claude Design, макеты в PDF, исходные изображения. **Менять не нужно** — это то, с чем мы сверяемся.

`docs/` — спецификация проекта и эта инструкция.

## Чтобы не мешать друг другу

Договоритесь заранее, кто какие файлы берёт. Содержание специально разложено по отдельным файлам — по файлу на категорию и на товар, — чтобы двое работали в разных файлах и правки не сталкивались.

Если всё же оба поменяли одно и то же место, git скажет об этом при `pull` и попросит выбрать нужный вариант. Это не поломка и ничего не теряется.
